# 内存与张量存活

分别记录模型 Flash、编译 scratch、运行时 Arena 用量、Arena 数组预留、其他静态 RAM、堆峰值、栈峰值、图像/驱动缓冲和各内存银行剩余容量。

追踪张量从产生到最后消费者的区间，包含分支、别名、原地操作、块缓冲与对齐。定位峰值时刻共同存活的对象；“各层张量大小之和”既不是峰值，也不是分配器布局。

跨设备/异步执行时，存活延续到 NPU/DMA 的最后实际访问完成。主图规划器未必看得到 delegate 内部缓冲；分别获取后端 scratch 并核对是否嵌入主图分配。参考 [内存放置与复用](../strategies/memory-placement-and-reuse.md)。

静态图理论存活峰值、编译器规划容量和运行时 allocator 报告分列。核对是否重叠：scratch 可能已在 Arena 内；堆/栈预留可能已经包含于链接段。总 RAM 不能把同一内存计两次。

为其他程序留空间，按每个可访问内存银行计算容量减预留，再结合栈/堆实测峰值和并发需求留余量。NPU 不可访问的 RAM、不可连续的空洞和已声明 Arena 内的未用区域不能直接算作可用工作区。

候选优先级：减少峰值张量并存 → 避免整幅中间结果 → 级联/分块和复用 → 重新选择峰值阶段结构。压缩末端 FC 不一定改变前段激活峰值。
