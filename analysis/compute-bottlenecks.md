# 计算、访存与调用开销

## 速度优化的入口：整理可得时间证据，不设逐层时间门槛

当前只使用模型静态数据与编译器结果。先整理下面的时间证据，做到报告实际支持的粒度即可；数据不足时记录缺口，不编造分层时间。没有逐层/块级时间，不阻止选择结构改写、融合、布局或分块候选进入实验。

1. **确定估算口径**：编译器总时间覆盖哪些 CPU/NPU 单元，是否含内存访问估算、是否覆盖回退；记录模型形状、dtype、目标时钟、带宽/延迟和调度配置。编译过程墙钟耗时单列。
2. **先做粗分段**：在报告覆盖范围内区分网络阶段、NPU 子图、CPU 回退及布局搬运。源码可发现 SDK 开销机制，但没有时间证据就标未知，不把它补进估算总时间。
3. **再定位模型内部贡献**：用目标编译器的阶段/子图/融合块估算，提供证据支持的粒度，不能把融合块拆成虚构的原始层时间。
4. **排序与解释**：按同口径估算贡献排序，列累计覆盖与未归因时间。关联调度、流量、物理张量和融合边界，判断慢在计算、访存还是交接；MACs 多并不自动代表耗时高。
5. **选择可影响总时间的候选**：有可信的时间分布时，优先考虑贡献较大且有可改机制的部分；没有分布时，按物化/搬运、物理形状、布局、融合边界等证据与实验成本排序，局部耗时和收益幅度保持未知。MACs 大可以作为计算规模的筛选线索，结合目标实现形成候选，但不能据此宣称时间占比或加速率。只有已知无重叠串行占比 p 和局部加速 s 时，才可用 1/((1−p)+p/s) 作量级判断；未知 p 时不用此公式。

输出至少包括：位置/范围、预计时间、占比及分母、编译报告来源、映射粒度、可优化机制、数据缺口。占比只能除以同来源、同口径的总估算；计算周期和访存周期可能重叠，先读清 cost model，不能把各列盲加。

## 只有整网或硬件 blob 时的实验路径

同时推进两条路径：按成本查 verbose、schedule、流量报告和成本模型；根据全图结构与已有编译证据选择可验证的候选。获取更多报告不是开始结构实验的必要前置。

- 对每个候选写出可核查的机制，例如消除一次重排、减少整幅物化、改变权重暂存或提高有效物理形状利用率；说明局部周期未知，提速幅度待编译确认。
- 在授权范围内实施单因素候选，做主机数值对照并重新编译；比较整网预计时间、周期分项、工作区、流量及实际融合/分配变化。整网改善可支持该候选在该配置下更有利，但不能自动还原某层耗时。
- 计算周期与内存惩罚的分项按成本模型定义解释。内存惩罚占比大只能提示相关调度/放置假设，不能单凭占比就确认由某个选项导致，也不能认为结构改写不影响它；结构、布局与级联都可能改变访存。
- 若候选编译失败、数值误差超限或内存违反约束，记录具体失败原因并淘汰/修正。若只有“小幅整网收益”，就按小幅收益报告，不为合理化实验补造局部时间。
- 同一后端、同图同配置的历史结果可以帮助排除重复实验；其他后端的收益只作线索，不能直接当本后端的结论。拆子模型会改变融合与调度，只作补充证据。

候选可以是“已选实验、收益待验证”；最终采用才需要满足目标、数值和其他约束。不要把“不能填写预计能快多少”误写成“不能选择此处做实验”。

## 时间与瓶颈的解释

区分父子范围与异步重叠，解释编译报告中循环、分块和流水是否已经计入；不把子图估算再加进其父区间。

按证据区分：

- 计算密集：MACs 大只是线索；结合编译器估算周期、利用率及实现方式判断。
- 访存密集：报告中的权重/激活访问量、内存层级、重复搬运及配置带宽是线索。逻辑读写量不等于实际总线流量。
- 调度低效：大量小算子、碎片分区、补齐、低通道利用率、重复启动或布局转换。
- 运行时开销：输入复制、重复范围缓存维护、锁/中断、CPU 回退与同步。

可用带宽和有效计算吞吐已知时，可用 max(MACs/吞吐, 访问字节/带宽) 做乐观量级下界；说明假设，不当作精确预测。

最小验证按不确定性选择：编译后分区和调度差异、单个子图的主机数值对照、同配置下的估算与流量比较。当前不安排固件插桩或硬件测时。结论写编译估算改善，不推导尚未取得的真实运行时间。
