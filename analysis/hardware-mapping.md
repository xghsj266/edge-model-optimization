# 模型与硬件联合映射

建立映射链：训练模块 → 导出节点 → 量化节点 → 编译后融合/分区 → NPU/CPU 执行单元 → 地址/缓冲区 → 驱动调用。

映射可能是一对多、多对一或无法恢复。保留名称、形状、消费者和编译调试信息等匹配依据；不能将融合块总耗时按 MACs 比例冒充原始层实测耗时。

逐个回答：

1. 算子是否在目标 NPU 上运行？有什么明确的放置/回退证据？
2. 逻辑通道数是否变成补齐后的物理通道数？剪枝是否跨过硬件粒度？
3. 中间张量是整幅物化，还是条带/块级级联？跨块是否重算 halo？
4. 权重和激活在哪级内存？缓存、带宽和访问路径有何证据？
5. 哪些边界需要量化、转置、复制、缓存维护或 CPU 同步？

输出“模型现象 → 平台限制 → 实际执行方式 → 开销机制 → 可区分假设的实验”。同样的 PReLU 或 group Conv 在不同编译器上不共享默认结论。
