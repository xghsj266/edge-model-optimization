# 其他优化目标的诊断链路

当前范围为静态分析、实际编译与主机数值对照。目标先由用户自由描述，以下路径供 AI 选择使用，不是提问选项。各目标共同遵循：固定基线及口径 → 拆解贡献 → 查原因 → 具体候选 → 验证 → 主指标与其他代价对比。取不到的数据写未知，不用其他指标伪造。

## 模型存储

**链路**：明确存储对象和预算 → 拆分产物组成 → 找主要贡献及重复数据 → 推导图/常量改法 → 编译验证 → 比较大小及速度/工作区代价。

1. 定义优化的是原始模型文件、编译模型、编码权重、全部常量、命令流还是完整固件；同时记录双方文件哈希与格式。
2. 按实际可解析的格式拆分权重、偏置/尺度、其他常量、命令流、元数据与对齐填充。检查是否重复嵌入、常量编码是否已压缩、是否有运行时外置依赖；不能直接把原始参数字节当编译权重字节。
3. 定位重复常量、可折叠仿射/常量子图、可删除的冗余表达及无效产物。仅改包或移到外部文件属于存储位置/打包变化，必须仍报告部署所需总字节。
4. 候选优先使用等价图改写、常量去重和后端支持的编码/打包方式。共享常量要求内容、量化语义、对齐和访问方式一致；常量折叠可能反而物化大表，要实际检查产物。
5. 主机数值对照后重新编译，按同一组成项比较。记录可能增加的运行时生成、加载、工作区和估算访存；不以压缩率直接推断执行速度。若包含固件，依赖与编译选项须可比。

**输出**：产物组成及大小贡献表、主要膨胀原因、候选修改位置、目标存储和部署总存储的前后变化。

## 访存与数据搬运

**链路**：明确数据通路和流量范围 → 拆分权重/激活/重排/复制 → 找高流量位置 → 判断重复读写与放置原因 → 编译验证 → 比较流量、预计时间和峰值内存。

1. 说明目标是编译报告估算总流量、特定慢内存流量、显式复制还是布局转换；区分每次推理和模型加载阶段。
2. 映射关键 producer/consumer、数据大小、内存层级、访问方向、分块次数及报告来源。逻辑张量字节、DMA 请求字节与总线实际流量分别记，不因同一数据经过多级内存而混加不同口径。
3. 查整幅中间结果物化、重复权重读取、transpose 往返、跨分区复制、halo 重算和 spilling。判断它们来自图表达、融合边界、布局、工作区压力还是放置约束。
4. 候选包括融合/布局传播、级联/rolling buffer、权重暂存、IO 共享和改变可用内存映射。确认是否真的减少物理搬运，不能按删除一个图节点就默认省下一次复制。
5. 比较同一编译配置的流量分项、预计周期、工作区和新增重算。若调整内存描述，需有真实硬件依据，不通过虚报带宽获得更好估算。后端不输出流量时只报告静态复制字节与覆盖范围，不宣称完整访存下降。

**输出**：数据流及放置表、高流量子图、可消除的物化/搬运证据、流量与时间/内存权衡。

## 减少 CPU 回退

**链路**：确认回退目标 → 建立算子及分区地图 → 逐项核实回退原因 → 推导受支持的等价表达 → 重编译核对放置 → 比较边界、工作区和预计性能。

1. 明确目标是减少 CPU 算子、减少分区交接、满足全 NPU 编译，还是减少运行时依赖。算子数量、原始节点覆盖率和编译后分区数不是同一指标。
2. 列出 CPU 节点及其形状、dtype、量化、布局和邻接分区；标出边界重排/复制。读取编译器的具体拒绝原因，区分不支持的语义、受限属性、动态形状、转换表达和编译配置。
3. 候选为原生表达恢复、常量/形状计算折叠、静态已知形状传播、受支持的等价子图或调整合法布局。固定形状必须符合用户输入契约；不能强制标记支持来掩盖缺失实现。
4. 主机数值验证后比较实际 CPU/NPU 放置、交接数量和边界缓冲。检查是否只是将一个 CPU 算子拆成很多 NPU 任务，以及是否引入额外复制或峰值。
5. 当 CPU 时间不在编译器成本模型内时，单列覆盖缺口。NPU 覆盖提高可以满足部署约束，但不能单靠覆盖率或算子数量宣称整网更快。

**输出**：逐项回退原因表、可改与暂不可改项、编译后放置变化，以及依赖/兼容性和时间估算覆盖的影响。

## 编译效率

**链路**：确定编译耗时范围 → 复现基线 → 按编译阶段定位热点 → 分析图复杂度/搜索原因 → 修改编译路径 → 对比编译耗时及最终模型质量。

1. 明确只计编译命令，还是含导出、转换、量化、编译的完整构建；原始阶段墙钟记录独立于预计推理时间。固定主机、并发负载条件、工具版本、缓存状态和计时边界。
2. 优先使用编译器提供的 timing 日志拆分导入、图重写、调度/内存搜索、权重编码和文件输出；没有日志就标未知，不从节点数估算编译阶段时间。
3. 排查重复转换/编译、图展开膨胀、无必要诊断输出、搜索空间和分配器迭代。避免把一次偶然墙钟抖动称为收益；必要时重复可比构建确认。
4. 可尝试等价规范化以减小编译图、避免重复构建、复用工具支持的缓存或收窄搜索。缓存键须覆盖模型、配置、目标和工具版本，不能用过期产物作为新模型的结果。
5. 比较实际编译耗时，同时保留预计推理时间、工作区、产物大小及主机输出对照。限制搜索可能缩短编译却损害最终调度；明确收益来自图变化还是构建流程。

**输出**：编译阶段耗时表、主要编译成本、可复现加速步骤及最终产物指标代价。

## 多目标权衡

**链路**：取得用户的目标与优先关系 → 固定多个基线及约束 → 对每个目标执行对应诊断 → 生成有限候选 → 统一比较 → 给出支配关系与取舍。

1. 为每个指标写清最小化/最大化、阈值、硬限制或可接受退化。用户未给权重时不自行发明综合分数；未明确优先关系且候选冲突时，先展示取舍供用户决定。
2. 每个候选使用同一模型契约、目标硬件及可比配置。配置是优化变量时显式列出差异，不能给不同候选使用有利的成本模型。
3. 单目标候选与组合候选分开记录，不能把两个独立收益直接相加；组合会改变融合、放置和调度，需要重新编译验证。
4. 先检查硬约束，再比较主目标与退化限制。仅在所有比较指标均可比且已取得时，判断 Pareto 支配：各指标都不差，且至少一项更好。未知指标不能当相等；细小估算差异需保留成本模型的不确定性。
5. 报告保留候选、被淘汰候选及理由。若有多个互不支配候选，明确谁快、谁省内存及其差值，不自动替用户决定偏好。

**输出**：统一候选对比矩阵、约束通过情况、主目标收益/其他代价、推荐依据与尚需用户选择的取舍。
