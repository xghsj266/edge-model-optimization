# 调度、内存与运行时

调度候选：改变工作区目标、条带/块形状、级联策略或权重缓存。每次保留原配置及编译报告，记录峰值、访存估算、补齐、重算和放置变化。更大的目标可能触发不同启发式选择，实际占用和耗时不保证单调。

将常量迁移到 SRAM 前，核实大小、对齐、NPU 可达性及命令流地址语义。额外模型输入可能改变编译调度；这与不改图的地址迁移不是同一实验。不要在缺乏指令格式依据时盲改命令流。

运行时优化单独归类：缓存范围去重、只读区域过滤、输出范围失效、减少复制/分区交接。先证明生产者/消费者及缓存一致性：

- CPU 写、NPU 读的数据必须满足 clean 和同步要求。
- NPU 写、CPU 读的数据必须满足 invalidate 和同步要求。
- 范围按缓存行对齐，处理别名、重叠范围和边界；同一缓存行的脏数据不能被错误丢弃。
- 输出范围优化仅在 CPU 不读取其他中间结果、输出范围可靠且无并发冲突时成立；未知地址走原路径。

当前只分析这些路径的源码机制及可改变的范围，不安排硬件验证或填写实际节省时间。若未来扩展至硬件验证，再保留完整同步对照并验证输出和计时；固定图结果也不能自动推广到摄像头、CPU 回退、调试读取或并发任务。
