# 内存放置与张量复用

先分清两种机制：**放置**决定对象位于哪级内存，**复用**决定哪些不同对象可共用同一地址。仅调整编译器带宽参数不会搬动物理数据；需核对生成地址、链接图、驱动 region 和实际运行路径。

为关键对象建表：对象/别名、字节与对齐、存活起止、访问次数/方向、生产者和消费者设备、可用内存池、访问权限及带宽/延迟证据。将 NPU、DMA 异步访问延伸到实际完成时刻；CPU 函数返回不是存活终点。

| 候选 | 条件 | 要比较的代价 |
|---|---|---|
| 重用不相交的张量空间 | 容量、对齐和可达性满足；所有读已完成 | allocator 规划、碎片、是否仍有额外 scratch |
| 原地逐元素/深度卷积 | 后续读及内核遍历顺序允许覆盖 | 临时行缓冲、其他消费者、数值一致性 |
| 关键权重/激活暂存到快内存 | 后端支持访问，容量足够 | 搬入开销、挤占级联空间、重复加载 |
| IO 共享缓冲或外置 | 生产消费的布局、dtype、生命周期匹配 | 复制是否消失；应用缓冲是否已计入总 RAM |
| 调整独立分支顺序 | 拓扑及异步依赖允许 | 峰值存活能否减少，关键路径是否增长 |
| 多内存池分配 | 物理映射、权限、性能准确 | 慢内存流量、碎片和跨池复制 |

优先验证峰值处的少数对象。总可用字节足够不代表有满足连续性与可达性的区域；输出外置也只是转移分配责任，不能把应用持有缓冲从总占用抹去。

参考 [ExecuTorch、ST 和 Vela](../analysis/optimization-sources.md)。复用与放置都需目标实现支持，不能直接覆盖编译器管理的 scratch 地址。
