# Edge Model Optimization

**以等价数学表达改写模型，改善模型在目标端侧硬件上的执行表现。**

*An AI skill that rewrites a model into mathematically equivalent forms the target edge compiler and hardware execute better, then verifies the gain with the real toolchain.*

同一个数学函数可以有多种写法。导出图里的一个激活函数可能被拆成四个逐元素算子，每个都整幅写回内存；一个推理期的仿射可以合进卷积权重；两侧布局转换可以被吸进常量。这些写法在数学上相同，但在 NPU 编译器眼中是不同的图：融合边界、中间张量、搬运和硬件利用率都不一样。

这个 Skill 指导 AI 找出这类表达差异，写出原式、改写式和成立条件，在目标 SDK/编译器上实际编译，再用数值对照和编译指标判断值不值得保留。

主要回答五个问题：**哪里可以改、为什么可能有效、具体怎样改、主指标改善多少、其他指标付出什么代价。**

## 核心方法

1. **找表达差异。** 对照训练图、导出图、量化图和编译后的图，找出被展开的算子、冗余的布局转换、整幅物化的中间结果。
2. **写出等价改写。** 每个改写给出原式、改写式、成立条件、涉及的节点与权重变化，以及拒绝条件。
3. **结合硬件约束。** 读目标编译器的支持条件、内存池和调度能力，判断改写能不能被实际融合、能不能减少搬运，而不是只看算子数量。
4. **验证。** 数学等价、浮点误差、INT8 逐值一致和任务精度是四件不同的事，分别检查。再用目标编译器重新编译，比较预计时间、工作区等指标。
5. **如实报告。** 先报主目标的前后变化，再报其他指标的代价。失败的和没收益的候选也保留。

### 等价改写的例子

| 改写 | 要证明的条件 |
|---|---|
| 推理期 BN 折叠进卷积权重和偏置 | 输出通道轴、分组、偏置、重新量化 |
| 逐通道仿射按 Concat 通道切分到各分支 | 连接轴，分支是否还有其他消费者 |
| 展开的 `ReLU(x) + α(x − abs(x))` 恢复成原生 PReLU | α 的广播与符号、目标原生支持、重定标 |
| 吸收可交换的布局往返（Transpose 折进下一层常量权重） | 轴、逐通道参数、量化轴同步重映射 |
| 合并连续线性变换 | 中间无非线性，注意 padding/bias 边界和权重膨胀 |

**实数上的等价不保证浮点或 INT8 逐值一致。** 运算顺序、舍入、饱和和重定标都会改变结果，必须单独验证。

### 配套的执行策略

分块、级联、张量复用、内存放置和编译参数也能改善执行表现，也会被分析和验证。但它们属于执行策略变化，报告里会明确标注。不能用一个编译开关的收益去代替等价结构改写的分析，也不会把纯配置调整称为新的数学等价变换。

## 如何使用

入口是 [SKILL.md](SKILL.md)。把模型、目标平台和可用资料交给 AI，并要求它读取这个入口：

```text
请读取 edge-model-optimization/SKILL.md，分析这份模型的优化空间。
模型：模型文件路径
目标平台：芯片及 NPU 型号
SDK／编译器：安装或源码路径
已有编译报告：报告路径（如有）
```

AI 会先开放式询问：

> 这次你希望模型主要改善什么？有没有必须满足的限制？

询问不提供选项或预选答案。目标已明确时直接记录，不重复询问；没有目标时只做文件识别和环境检查。可以不给数值阈值，之后按改善幅度和代价讨论。

目标明确时可以直接说：

```text
希望降低编译器预计推理时间，同时控制工作区占用。
请先诊断并给出候选；允许在独立目录中修改副本、重新编译和做小样本数值对照。
每个步骤写出结论，最后在聊天里给我简化版改进与结果。
```

**复用方式：** 复制整个 `edge-model-optimization/` 目录并保留内部相对路径。只复制 `SKILL.md` 会缺少参考文件。本目录保留通用方法、模板和辅助脚本；每次任务的模型、编译产物、实验数据和报告保存在使用项目的输出目录中。

## 工作流程

```text
开放式询问目标与约束
        ↓
固定模型哈希、输入输出契约、工具版本和基线
        ↓
模型结构分析 ＋ SDK／硬件约束提取
        ↓
联合定位瓶颈，记录证据范围和未知项
        ↓
推导等价表达，说明成立条件和目标硬件的收益机制
        ↓
一次只改一个因素：修改副本、验证数值、重新编译
        ↓
比较主目标收益与其他指标代价
        ↓
详细报告 ＋ 聊天摘要（保留成功与失败候选的结论）
```

参考： [模型结构](analysis/model-structure.md)、[SDK 约束](analysis/sdk-capabilities.md)、[硬件映射](analysis/hardware-mapping.md)、[优化目标说明](analysis/optimization-objectives.md)（供 AI 内部映射用户需求，不是问卷）。

### 不同目标怎样分析

| 目标 | 分析链路 |
|---|---|
| 推理速度 | 整理可得时间证据 → 分析计算/访存/调度机制 → 选择候选 → 比较整网及可得分项的编译估算 |
| 内存 | 区分工作区/峰值/内存池 → 追踪张量存活 → 找峰值共同存活对象 → 验证复用、级联和放置 |
| 模型存储 | 拆分产物组成 → 查重复和膨胀 → 折叠、去重或编码候选 → 比较存储及其他代价 |
| 访存与搬运 | 拆分读写与数据通路 → 查物化、重排、重复读取 → 验证布局、级联和暂存 |
| CPU 回退 | 建立放置地图 → 核实具体拒绝条件 → 尝试受支持的表达 → 比较回退与交接变化 |
| 编译效率 | 复现编译墙钟 → 拆分阶段 → 查图膨胀、搜索或重复构建 → 比较耗时和产物质量 |
| 多目标 | 确定优先关系与限制 → 分别诊断 → 统一候选矩阵 → 判断约束与取舍 |

速度与内存分别见 [耗时分析](analysis/compute-bottlenecks.md) 和 [张量存活分析](analysis/memory-lifetimes.md)；其他目标见 [诊断链路](analysis/other-objective-workflows.md)。

只有整网或单个硬件 blob 的时间时，不会按 MACs 比例伪造逐层耗时。Skill 允许依据结构和编译证据选定有机制支撑的假设，用整网前后对比检验。局部贡献在验证前写“未知”。

## 覆盖的方向

| 方向 | 重点检查 |
|---|---|
| 图结构与等价表达 | 原生算子恢复、常量/仿射折叠、冗余子图与分支 |
| 融合与布局 | 融合边界、中间张量物化、transpose 往返、轴和量化参数映射 |
| 分块与调度 | 条带/patch、级联、分支顺序、重算与权重暂存 |
| 内存规划与放置 | 张量存活、别名、安全复用、多内存池、工作区预算 |
| 编译器与 SDK 配置 | 可控参数、版本限制、默认与候选配置的影响 |
| 优化判断 | 主目标达成情况、其他指标变化、失败原因和多目标取舍 |

剪枝、蒸馏、低秩近似和改变量化位宽是补充方向，不是默认候选。优先在既有模型语义与数值格式下，改进结构表达和执行方式。已有量化轴、尺度、舍入与饱和仍要检查。

已有平台参考：[ST Neural-ART](platforms/st-neural-art.md)、[Arm Ethos-U / Vela](platforms/ethos-u-vela.md)、[Rockchip RKNN](platforms/rockchip-rknn.md)。其他平台按同一证据字段建立约束表，不套用现有平台的参数。

## 报告与聊天输出

详细报告使用 [诊断报告模板](templates/diagnostic-report.md)。每个执行步骤记录：

- 检查或执行了什么，输入与证据在哪。
- 结论、关键数据和可信程度（已确认／有证据的推测／待验证）。
- 未执行、失败或证据不足的原因。
- 这个结论如何决定下一步。

每个候选用 [优化结论模板](templates/optimization-finding.md)。最终先列主目标的基线、候选、绝对和相对变化、达标情况，再列其他指标及不利变化。

聊天里同时给简化版：**改了什么 → 主指标变化 → 其他代价 → 建议保留哪版 → 报告链接**。不能只发文件路径；未实施的建议和缺失数据必须如实说明。

## 指标比较脚本

[compare_candidates.py](scripts/compare_candidates.py) 只用 Python 3.10+ 标准库。它读取已整理的 JSON，先比较主目标，再列其他指标的变化和退化限制。它不解析模型或编译日志。

```bash
python scripts/compare_candidates.py objective.json baseline.json candidate.json
```

三份 JSON 的字段与示例见 [指标契约](scripts/metrics-contract.md)。示例数字只说明格式，不会自动成为用户目标。

可比较预计推理时间、编译墙钟、scratch、峰值 RAM、模型字节、常量字节、估算流量、MACs 以及 CPU/NPU 算子数。要求 `measurement=compiler`；缺失指标显示未评估。目标硬件、工具版本、输入契约、时钟或估算范围不匹配时，脚本拒绝比较；编译墙钟还要核对主机与缓存状态。

候选改变了编译选项时，要在报告中列出差异。脚本查不了所有配置细节。它也不验证数值一致、任务精度或统计显著性。

## 边界

- 这是指导 AI 分析、实施小范围候选并整理证据的 Skill。已有指标对比脚本，尚未内置统一的模型解析器、张量存活提取器、编译报告解析器或自动参数搜索器。
- 能看到什么取决于目标模型、SDK、编译器和能取得的报告。不保证恢复融合 blob 内部的逐层信息。
- 当前结果采用静态和编译侧口径。编译器预计推理时间和实际编译耗时分别记录。估算的改善不是硬件实测收益。
- 主机输出一致、小样本误差和任务精度是不同的证据。
- 分析请求不自动授权重训、全量数据评估、烧录或正式实验报告更新，范围以用户授权和所在项目规则为准。
- 中间产物放在所在项目约定的临时目录，不污染根目录。
